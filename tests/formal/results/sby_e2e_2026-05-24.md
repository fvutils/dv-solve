# yosys-sby end-to-end with dv-solve — 2026-05-24

First successful end-to-end run of yosys-sby driving dv-solve as the
`smtbmc` backend. counter_assert.sv (4-bit counter, two assertions)
verified through BMC.

## Setup

- `tests/formal/sby/smtio_dvsolve.patch` applied to the vendored
  `packages/yosys-bin/share/yosys/python3/smtio.py` to add the
  `dv-solve` engine.
- `packages/yosys-bin/bin/dv-solve-smt2` symlink to the local build.
- `[engines] smtbmc dv-solve` in the sby file.

## Bugs found and fixed via this integration (today)

1. **bvnot missing bit-width mask** — `~5` on an 8-bit value gave
   `-6` instead of `250`. Without the mask, propagation chased a
   negative bound and dv-solve crashed with 65 GiB OOM on the very
   first BMC step. Fix: mask the result by `(1 << width) - 1`.
2. **push/pop didn't release aux SolveProblems** — popped
   assertions stayed in the model-validation list and silently
   downgraded sat → unknown.
3. **OR-of-extract dropped to "uncompiled"** — `_bool_to_var` and
   `_classify_or_leaf` didn't accept EXTRACT shapes. Materialise
   via `_value_to_var` first.
4. **LIFO var init skip** — builder's `vars_head` is LIFO; the
   "id >= ctx->n_vars" gate skipped lower-id new vars whose slots
   the loop's earlier walk had already passed. Fix: two-pass, first
   pre-grow n_vars to the max new id.
5. **_fresh_aux collided with backend-internal aux IDs** — frontend
   `fe->n_vars` doesn't include backend-allocated constant-aux /
   ITE-result aux from `solver_compile`. New frontend IDs landed
   on existing backend slots. Fix: `_next_var_id` skips past
   `ctx->n_vars`.
6. **solver_restore left post-cp props re-activatable** — marked
   ENTAILED, but `solver_reset` cleared the flag on the next solve.
   The stale push-scope propagators fired against the reused aux
   IDs post-pop. Fix: NULL out post-cp `prop_refs[i]` and roll
   `n_props` back.
7. **Learnt-clause scope leak** — CDCL clauses learnt inside a push
   reference var IDs that get reused for new aux vars post-pop.
   Fix: roll back `clause_db.n_clauses` and NULL out clauses[i]
   in `solver_restore`.
8. **concat with const operand dropped binding** — `(concat #b0
   v)` (very common in yosys output) had a const hi side that
   `_is_var` rejected → constraint not compiled → false sat. Fix:
   materialise both operands via `_value_to_var`.
9. **stderr polluted SMT2 response channel** — yosys-smtbmc runs
   the solver with `stderr=STDOUT`, so model-validation messages
   on stderr were read as protocol errors. Fix: when stdout is a
   pipe, divert `fe->err` to `/tmp/dv-solve.log` (or `$DV_LOG`).
10. **_add_var overflow** — n_vars could jump past vars_cap via
    the new _next_var_id sync. The `==` grow check missed the
    multi-slot bump. Fix: convert to `while (n_vars >= vars_cap)`.
11. **SMT2_MAX_FUNS=64 too small** — yosys-smtbmc emits one
    `define-fun` per UNROLL step; 64 caps at ~5 BMC steps. Bump
    to 8192.

## Reproducing

```
# After applying tests/formal/sby/smtio_dvsolve.patch:
ln -sf "$(pwd)/build/dv-solve-smt2" packages/yosys-bin/bin/dv-solve-smt2
mkdir -p /tmp/sby_test && cd /tmp/sby_test
cp /home/mballance/projects/fvutils/dv-solve/tests/formal/sv/counter_assert.sv .
cat > counter_dv.sby <<'EOF'
[tasks]
bmc
[options]
bmc: mode bmc
bmc: depth 7
[engines]
smtbmc dv-solve
[script]
read -formal counter_assert.sv
prep -top counter_assert
[files]
counter_assert.sv
EOF
sby -f counter_dv.sby bmc
```
